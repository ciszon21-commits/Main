## 1. 交付目標與排序原則

讓建築師在同一 Rhino 工作平台，選擇模型與必要環境條件，取得可解讀、可比較、可匯出的多種視覺成果。優先補齊多個最小可用流程；完整參數、全量數值操作工具與 122 入口逐項獨立頁面後排。

細部數值「介面與工具」後排；原生數值正確性、必要資料型別、單位、時間與模型條件、來源、適用限制與結果驗證仍是每個功能的出口門檻。圖片不代替真實求解；不得用氣象風資料或假向量填補 CFD，也不得把日射色圖標成表面溫度／MRT。

保留 C#／RhinoCommon／Eto／Grasshopper／既有 Adapter 與求解行為。各能力接入單一 HubWorkspacePanel 的快取內部視圖；不新增獨立 Dock、不重寫整套介面或物理核心。必要 UI 改善隨功能交付，V2 大型互動架構仍另規劃。

UI 新參考：使用者提供「Rhino MCP UIUX」對話與 Eto.WebView 建議，採 [Eto 外框＋WebView 視覺成果探查](WEBVIEW_UI_STRATEGY_2026-10-05.md)。先做只讀圖表／結果頁 MV-U0，原生選取與 C# 求解保留；未通過宿主驗收前不全面替換。U0 為條件式追加 2–4 原始人日，含一次 25% 為 3–5 人日；不含全介面遷移。核心加 U0 為 50–90、含風場加 U0 為 65–118 人日，統一從原始總量計算，不加已取整子預算。

## 3. 操作與視覺規則

主流程保留：模型 → 環境 → 模擬設定 → 檢核／執行 → 結果 → 比較／匯出。能力選擇以「日照、陰影、輻射、風與圖表」組織；氣象、地點、時間與細部資料工具作共用條件或輔助入口。

- Rhino 視埠是模型結果閱讀區；圖表則用清楚的座標／圖例，避免塞滿窄側面板。以摺疊進階設定、合理預設與必要資訊降低第一次操作負擔。
- 克制的分類主題色、統一字級／間距／向量圖示；結果色階獨立於 UI 主色。檢查淺／深色、窄／寬停靠、長標籤及物件重疊。
- 各模組预覽分別擁有、可開關／定位／清除；保留模型輪廓、圖例與來源。改呈現不重算；改模型／日期／取樣等物理條件明示需重算。
- KPI 僅保留最小／最大／平均、單位、分析期間及必要取樣資訊；詳細數表與專業設定摺疊。未知條件不得以預設值靜默補齊。
- 同模組 A／B 先檢查條件；幾何取樣未對齊只並列摘要，不能產生假差值色圖。共同色階僅透過受驗證原生參數；否則各自圖例並列並明示範圍。
- 匯出首批當前視圖／圖表 PNG、精簡 HTML 摘要及完整 JSON。含條件、版本、資料／模型來源、單位與假設；各能力只承諾已驗證的匯出格式。
- 不提供假進度或無效取消。既有 GH 同步求解界線保持；CFD 長作業的狀態／日誌／停止方式須獨立探查並驗證。
