# 日照方案檔案與恢復 · 0.10.7 候選

0.10.7 在現有日照模組第六階段加入「匯入方案比較 JSON…」，接續 ROADMAP 的 X1 持久方案工作。方案以檔案留存，可以在新的 Rhino 工作階段恢復比較。此批不接入新的 Ladybug 元件，也不提高正式功能覆蓋。

## 使用流程

1. 完成真實日照分析，為結果命名並「儲存完成結果為方案」。單一方案也可匯出，不必先有兩個方案。
2. 用「匯出比較 JSON…」保存所有方案及基準／比較選擇。完整結果 JSON 是單次分析格式，不能當作方案比較檔匯入。
3. 下一次開啟 Rhino，進入同一工作平台的「日照時數 → 06 比較／匯出」，選取「匯入方案比較 JSON…」。匯入成功後恢復方案名稱、完整原生結果與比較選擇。
4. 可追加其他不同名稱的方案檔；目前方案不被覆蓋。若名稱重複，整批拒絕，使用另一個新工作階段或重新命名來源方案後再匯出。

方案仍需手動匯出；沒有背景存檔、雲端備份、跨模組方案庫或模型重建。關閉 Rhino 會釋放未匯出的工作階段資料。

## 契約與拒絕條件

匯入入口 `SunHoursPanel.ImportScenariosJson` 使用 Core `SunHoursArchive.Parse`，在變更既有方案前完成整批檢核。

| 項目 | 支援／拒絕條件 |
| --- | --- |
| 版本與格式 | `SchemaVersion=1.0`、`Scenarios`、有效 `BaselineIndex/CandidateIndex`；Metric 必須為格點算術平均；不採信檔內 Interpretation，依結果重新計算文字 |
| 容量 | 檔案 UTF-8 資料上限 64 MiB；匯入後合計最多 20 個方案；至少 1 個方案 |
| 名稱 | 1–80 字元、不含首尾空白或控制字元；檔內與既有方案不分大小寫不得重複 |
| JSON 結構 | 必要欄位完整、非 null；拒絕重複欄位、損壞格式及不支援版本；地點時區可保留原生推定的 null |
| 時數與統計 | `h`；每點 1/timestep 的取樣權重；時數不得超出可用太陽向量；Count/min/max/mean 須與完整 Values 相符 |
| 幾何與取樣 | 格點、網格面與數值數量對齊；有限座標、有效三角／四角面索引、色彩數量；單位太陽向量、原取樣序列中的 sun-up HOY |
| 來源 | 保留模型、太陽來源、Ladybug 元件指紋、模型尺度、求解器、版本、警告及時間；不因本機沒有舊模型 UUID 而拒絕歷史檔 |

指紋與結構檢核無法證明外部檔案的真實性。匯入資料明示「歷史結果、未重新求解、未核對目前模型」；檔案來源由使用者確認。匯入只恢復比較資料，不把舊 UUID 綁定目前文件，不套用網格、預覽、輸入或完成結果。故空白工作階段匯入後「匯出完整結果／儲存完成結果」仍停用。

太陽來源比較同時核對實際地點／北向／時間制／步數／HOY／向量與既有來源／元件摘要。即使摘要未改，實際北向不同也不顯示差值。網格間距、偏移、自遮蔭與模型指紋差異仍揭露；數值為格點算術平均，不是面積加權、照度或法規合規判定。

## 驗證邊界

42 項檔案／契約檢查、17 項 Rhino 匯入操作及 13 項新程序恢復檢查通過。0.10.6 舊檔與 0.10.7 六方案檔可讀回，全部 NativeResult 欄位完全相等；匯入不求解、不改模型。另有 161 項全平台原生回歸、32 項狀態／文件隔離、Core 25、MCP 工具 12；四張 320／480 淺色離屏圖已檢視。

正式 OpenFileDialog 已開啟，但 accessibility 無法可靠讀取，取消後以正式 API 完成恢復。尚未宣告原生檔案選取成功；比較成功存檔、完整 Dock／深色／全鍵盤／滑鼠後選與跨機仍待驗收。詳見 [本輪驗證](HOME_VALIDATION_0107.md)。
