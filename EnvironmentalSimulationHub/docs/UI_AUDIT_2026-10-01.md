# Architectural performance platform UI audit

Scope: code-built native Eto/WPF Rhino panels; no XAML or web application. Audit uses source and production-panel renders from 0.7.0–0.8.3. Core simulation contracts, RhinoCommon geometry and isolated original Grasshopper components are retained.

| Finding | Impact | 0.8.3 intervention |
|---|---|---|
| Overview treats climate utilities as sequential cards | No distinction between a simulation and supporting data tools | Workflow index, executable solar workflow and compact environment-tool directory; future engines explicitly planned |
| Repeated outlined groups, duplicated section helpers | Dense engineering utility appearance | Shared ruled sections, host colors, typography and spacing; no decorative cards/shadows |
| Basic inputs omit existing advanced request settings | Power users must call JSON APIs | Collapsed CPU, sky density, reflectance and sensor offset controls with original defaults and preflight |
| API-selected hours lost on a subsequent button run | UI can accidentally change scientific scope | Retain supplied hours and settings; explicit annual-reset action |
| Results present only a paragraph of numbers | Difficult to interpret magnitude and color | Prominent average/minimum/maximum/count/units; exact mesh-color samples and recorded execution conditions |
| No target criterion | No meaningful pass/fail interpretation | Optional inclusive project target range; cell counts, not a regulatory assessment |
| Export mixed into result actions | No scenario workflow | Separate Compare / Export stage, named session snapshots and full-provenance JSON |
| Native color scales vary by run | Colors can mislead cross-scenario comparison | Never recolor/interpolate; numerical comparison and explicit per-run-scale notice |
| No viewport location action | Hard to find result region | Zoom to panel-owned preview bounds in its originating document |
| Synchronous UI-thread Grasshopper solve | Rhino can pause; fake cancel would be misleading | Honest execution state and limitation; async/cancellation remains a separate runner milestone |

Unified analysis sequence: Geometry / Model → Environment / Weather → Simulation settings → Validate / Run → Results → Compare / Export. Utility panels retain task-specific steps within the same design system. Future adapters should implement the same boundary before being presented as executable engines.

Verification: separate build, original-solver regression, native control interaction, comparison/criteria/ownership checks and visual evidence. Offscreen native panel rendering establishes layout in the current host theme, not full dock, dark-theme, keyboard or file-dialog acceptance.

## Topic hierarchy refinement — 0.8.5

User direction: V1 stays in the current framework; defer the larger interactive interface to V2 after functional completion. The next audit found that shared headings lacked categorical identity and module entry actions lacked consistent glyphs. HubVisuals now supplies restrained theme tokens and native vector icons; HubUi applies them without new card frames or core changes. Main titles remain full-width beneath the compact brand line.

Native 0.8.4 renders exposed a separate text issue: Eto Label parses ampersands as mnemonics by default, removing the literal character from “Time & periods” and “Climate & design days”. Shared informational labels now explicitly disable mnemonic parsing. The corrected binary is 0.8.5; the already-loaded 0.8.4 files remain intact.

Acceptance checks actual host heading/secondary-text contrast and opacity, both palette variants on reference backgrounds, label mnemonic flags and 320/480 px production-control layouts. Token contrast is not dark-theme interaction verification. Numerical values and exact native cell-color samples retain their original behavior. Evidence: topic_085_acceptance.json, topic_085_palette.json and ui_085/capture.json.
